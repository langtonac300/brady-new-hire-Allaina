# Welcome — Paid Search Analyst, Brady Americas

This is your repo. It holds everything you need for your first 90 days: what to learn, the
projects you'll work through, a place to put your own work, and a way to see how far you've
come.

**Nobody expects you to know any of this yet.** You were hired for how you think, not for
what you already know about paid search. The first month is designed to be reading,
watching and asking questions — you won't touch a live account in week one, and that's
deliberate.

## How the 90 days are shaped

| Phase | Days | What you're doing |
|-------|------|-------------------|
| **Learn** | 1–30 | Understanding the tools, the business, and how Brady measures things. **Read-only** — no live changes |
| **Assist** | 31–60 | Doing the work with a safety net. Everything reversible, everything reviewed before it ships |
| **Own** | 61–90 | Running your accounts day to day, bringing recommendations rather than questions |

Projects start at about an hour each and grow to week-long by the end. That's on purpose —
the length is part of what's being trained.

## Three things that will save you time

**1. Ask early and ask in chat.** Alex's 1:1s are analyst-led and he doesn't push tasks
through a tracker, so messaging in Google Chat is the *expected* way to get unblocked — not
a sign you're behind. If you're stuck at 10am, don't wait until Friday.

**2. Being confused by attribution is normal.** The single most common beginner mistake at
Brady is quoting Google Ads' "Conversions" as revenue. The team's reported numbers come
from a different model entirely. Everyone finds this disorienting for a few weeks — it's
covered properly in the fundamentals, and there's no shame in asking twice.

**3. Never quote a number without knowing where it came from.** Several of Brady's
spreadsheets and dashboards disagree with each other, and some of them are wrong in known,
documented ways. "Where is this from and what's the caveat?" is the most useful habit you
can build in your first month.

## Using this repo

- Put your own work in **[`04-my-work/`](./04-my-work/)** — notes, drafts, deliverables,
  anything you want a second pair of eyes on.
- You don't need to be a git expert. Uploading a file through the GitHub web interface is
  completely fine.
- If something in here turns out to be wrong or out of date, **fix it or flag it.** You'll
  spot things a person who's been here three years can't see any more, and that's genuinely
  valuable — say so.

**Three house rules if you do edit or add a file** — this repo gets touched by a lot of
people, so a little tidiness keeps it usable for the next one:

1. **Edit the file that's already there** rather than making a second copy. A `pdc-primer-v2`
   sitting next to `pdc-primer` is how a repo turns into a maze — change the original.
2. **If you add a file, add one line for it** to that folder's `README.md`. A folder's README
   is its table of contents, and a stale one is worse than none.
3. **Keep personnel and performance matters out of here.** Those conversations live with Alex
   and HR, not in version control.
